# ARMOS custom kernel (M5, variant 3)

ARMOS uses its own Linux 6.18 kernel: vanilla sources, an ARMOS configuration,
a boot banner and a custom boot logo. `gentoo-kernel-bin` remains available as
a fallback.

## What is ARMOS-specific

- `configs/kernel/config-6.18.0-armos` — small x86_64 defconfig-based set: virtio,
  ext4/xfs/btrfs, squashfs, overlayfs, loop, dm-crypt, NVMe/AHCI/USB, DRM
  (virtio/i915/amdgpu/nouveau), HID, audio and common network drivers.
- `overlay/sys-kernel/armos-kernel/files/armos-branding.patch` — prints
  `ARMOS 1.0 GEN: custom kernel` during early boot.
- `overlay/sys-kernel/armos-kernel/files/logo_linux_clut224.ppm` — 80x80 boot
  logo with the ARMOS "A" monogram in the 224-colour Linux logo format.
- `CONFIG_LOCALVERSION="-armos"` — the kernel reports `6.18.0-armos`.

Both assets are generated by `build/make-kernel-assets.py`.

## Build (host without root)

The kernel source tree must live at a path without spaces, for example
`/home/ghost/armos-kernel-work/linux-6.18`. Host needs `bc`, `flex`, `bison`
and libelf headers. When these are not installed system-wide, extract the
tool RPMs into a prefix and point `KERNEL_TOOLS` at it.

```bash
KERNEL_DIR=/home/ghost/armos-kernel-work/linux-6.18 \
  bash build/kernel-config.sh

PATH=/home/ghost/armos-kernel-work/tools/usr/bin:$PATH \
KERNEL_TOOLS=/home/ghost/armos-kernel-work/tools \
PROJECT_ROOT="$PWD" \
KERNEL_DIR=/home/ghost/armos-kernel-work/linux-6.18 \
  bash build/kernel.sh
```

Result: `build/kernel-install/vmlinuz-6.18.0-armos`, modules and `System.map`.

## Install into the rootfs and test

```bash
./build/container.sh /armos/build/kernel-install.sh
KVER=6.18.0-armos GUI=1 ./qemu/run-base.sh
```

To go back to the fallback kernel, just run `qemu/run-base.sh` without `KVER`.

## Ebuild

`overlay/sys-kernel/armos-kernel/armos-kernel-6.18.ebuild` performs the same
steps through Portage: it fetches `linux-6.18.tar.xz`, applies ARMOS branding,
uses our config and installs the image and modules under version `6.18.0-armos`.
